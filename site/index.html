A browser extension that spots payment scams in marketplace chats and offers a PayPal order instead.

Try PayBrake in 2 minutes

No install needed to look: the demo page shows a built-in preview of the card.

Open the demo Download the test build

To run the real extension in Chrome:

  1. Download paybrake-extension.zip from the public demo (no GitHub account) and unzip it.
  2. Open chrome://extensions, turn on Developer mode, click Load unpacked and pick the unzipped paybrake-extension folder.
  3. Open the live demo. PayBrake shows a card under the risky message in the bike chat.

The test build works on our demo page only. The source repo is private until judging, so this page does not link to GitHub, the README or issues.

How accurate the rules are

  • 45.6%of scam messages got a card (325 / 713)
  • 0.9%of normal messages got a card by mistake (8 / 860)

Rules only, rules v4, on the held-out test split of 1,573 messages from public datasets. Remeasured 3 Nov 2026 in eval/real/RESULTS.md (precision 0.976). Not marketplace chats. An older rules-plus-AI run (26 Oct, rules v3, Typesafe jev-1.14.0) was not repeated after the later detectors, so those figures are not listed here.

Privacy

The rules run in your browser. AI check on all chats is on by default in this build. Turn it off in the extension's Settings and no chat text leaves the browser.

With it on, PayBrake masks emails, phone numbers, card numbers, IBANs (all but the last 4 characters), ID numbers and one-time codes before anything is sent. Names, addresses and other free text are not masked. Only the other person's messages can raise a card, and your newest message is included for context. The masked chat goes to the server in Settings (the free test server by default). That server passes it to its AI provider, Typesafe jev-1.14.0, and keeps nothing. The free test server does not send the chat to a second provider. On your own server, LLM_FALLBACK=openrouter does: a Typesafe failure other than a rejected request (a bad key or any other 4xx) sends the same masked chat to OpenRouter.

PayBrake never types or clicks in the chat. If the AI does not answer within 6 seconds, the rules result stands.

Details

How it works

  • The rules are mostly English and Danish, with some Swedish phrases (på Wise, Swish, and a few handover lines). They check the open chat for risky payment requests. The AI check, on by default, also reads every chat and can add a card the rules missed. It cannot raise the rules level.
  • Switch to a PayPal order creates a PayPal Orders v2 order (sandbox) for the item in the chat. With no sandbox keys, the same steps use a mock order, as in the screenshot. Live PayPal is refused.
  • Pay anyway hides the card and saves your choice on your device.

Limits

  • Not a full Swedish ruleset. Coverage is English and Danish, plus those Swedish phrases. The test build runs on the demo page only, not on real marketplace sites.
  • The numbers above are the rules-only remeasure on public datasets, so real marketplace accuracy is unknown. The 26 Oct rules-plus-AI run was not repeated after later detectors.
